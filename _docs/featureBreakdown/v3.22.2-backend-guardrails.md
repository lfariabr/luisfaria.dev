## Overview

Three guardrails and two doc fixes, all surfaced by the first retro of a Matt Pocock-style epic.

## Problem

1. **Type errors found only by Jest.** Four of the epic's twenty red runs were plain `tsc` errors; nothing ran `tsc --noEmit` or ESLint on the backend before tests, and CI only built and tested it.
2. **Redis on :6381 was tribal knowledge.** Documented in a Claude memory file and in old breakdown tables, not in the repo. The suite fails with `ECONNREFUSED` without it.
3. **Stale pointers.** `CLAUDE.md` listed seven resolver domains out of eleven, no REST routes, and five of eight models. `CONTEXT.md` named concepts with no path to the code.

## Changes

### 1. Backend ESLint (`backend/eslint.config.mjs`)
Flat config: `@eslint/js` recommended + `typescript-eslint` recommended. Overrides: `require()` allowed in `src/__tests__/**` (Jest mocking idiom) and in `.js` scripts with Node globals; `scripts/mongo-init.js` declares its mongosh globals in-file. `no-explicit-any` is a warning, and `--max-warnings 123` (the count at adoption) fails lint when the total exceeds that baseline. It stops the count growing; it does not flag an individual new `any` if another was removed. Cleanup to zero is a follow-up.

Sixty-six real violations fixed: unused variables and imports in tests, `@ts-ignore` → `@ts-expect-error`, `{ cause }` on three rethrown errors, a useless regex escape, an intentional control-character regex marked as such.

### 2. Scripts and CI
`npm run lint`, `npm run typecheck`, and `pretest` → `scripts/ensure-redis.sh`. CI backend job runs `npm run lint` before `npm run build`.

### 3. Redis pretest guard (`backend/scripts/ensure-redis.sh`)
Reads `REDIS_URL` from the environment or `.env`, probes the port; when local and silent, starts `redis-test-<port>` from `redis:alpine` and waits for it. Non-local or docker-less failures exit 1 with a one-line instruction. In CI the service is already up, so it is a no-op.

### 4. Pre-commit hook (`.githooks/pre-commit`)
Runs typecheck + lint for whichever package has staged files. Dependency-free; enabled per clone with `git config core.hooksPath .githooks`.

### 5. Pointers
`CLAUDE.md`: new scripts, full resolver list, REST routes, services, models, Redis requirement and suspected `cookieAuthE2E` flake, pre-commit pointer. `CONTEXT.md`: `_Lives in_` line under each glossary term.
