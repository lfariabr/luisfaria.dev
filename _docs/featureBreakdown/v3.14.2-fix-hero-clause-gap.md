## Overview

Follow-up to v3.14. On the live site (desktop + mobile) the hero showed a large dead vertical gap
between the green rotating clause and the subtext. Fixed by normalizing the rotating clause lengths
so every frame wraps to the same number of lines at each breakpoint.

## Problem

The crossfade in `HeroHeadline.tsx` grid-stacks all four clauses in one auto-height grid cell, so
the cell permanently reserves the height of the **tallest** frame. Two clauses wrapped to 2 lines at
hero font sizes:

- `with ML that ships to production.` (33 chars)
- `from raw data to real decisions.` (32 chars)

So whenever a 1-line frame was shown (`that pay for themselves.`, `end-to-end, frontend to infra.`)
the reserved second line rendered as empty space — the odd gap. This is the zero-layout-shift
trade-off of the grid-stack approach.

## Changes

Copy-only edit to `HERO_FRAMES` in `content/profile.ts` — trim the two long clauses into the
~24–30 char band so all four wrap identically (1 line desktop, 2 lines mobile):

| Lens | Before | After |
|------|--------|-------|
| ML Engineer | `with ML that ships to production.` | `with production-grade ML.` |
| Data Engineer | `from raw data to real decisions.` | `from raw data to decisions.` |
| Full-Stack Engineer | `end-to-end, frontend to infra.` | _unchanged_ |
| Hybrid | `that pay for themselves.` | _unchanged (canonical)_ |

No component/CSS changes — the grid-stack already guarantees zero layout shift; normalizing the copy
is what removes the dead space. `HERO_CANONICAL_PHRASE` and `HERO_CANONICAL_INDEX` are untouched, so
the SSR/no-JS/SEO accessible name is identical.
