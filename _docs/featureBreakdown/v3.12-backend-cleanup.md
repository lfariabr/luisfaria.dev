## Overview

First slice of the Phase 3 backend cleanup from the architecture audit — the safe, contained items: remove dead code, fix the `checkRole` role comparison, and unify the split rate-limit error code.

## Changes

### 1. Dead code
Deleted the three empty/`// TODO` subscription files (not imported anywhere):
`resolvers/projects/subscription.ts`, `resolvers/articles/subscription.ts`, `resolvers/screams/subscription.ts`.

### 2. `checkRole` → `UserRole` enum
`utils/authUtils.ts` compared roles against the loose lowercase string `'admin'` (legacy). Since `getUser()` normalizes `context.user.role` to the uppercase `UserRole` enum, the default and fallback now use `UserRole.ADMIN`. Call sites (which pass `'ADMIN'` explicitly) are unchanged.

### 3. Unify the rate-limit error code on `RATE_LIMITED`
The codebase emitted two codes for the same concept: `RATE_LIMITED` (chatbot, screams, APOD service) and `RATE_LIMIT_EXCEEDED` (`utils/applyRateLimit.ts`, used by the APOD resolver). Standardized on **`RATE_LIMITED`**:
- Backend: `utils/applyRateLimit.ts`.
- Frontend: `components/apod/ApodDialog.tsx` (2 checks) — so the APOD rate-limit UI keeps working.
- Tests: `apodResolvers.test.ts` (3) + frontend `Apod.test.tsx` (1).

## Out of scope (slice 3b)
Standardize `screams`/`resend` error handling (raw `GraphQLError` / `new Error` → `Errors.*`); consolidating the two rate-limit utility *functions* (`rateLimit` middleware vs `applyRateLimit`).
