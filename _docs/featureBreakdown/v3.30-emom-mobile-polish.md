## Overview

The EMOM tracker (`/admin/emom`) works well on a laptop. On a phone mid-set it had collisions, a misleading last-minute label, and an abrupt hand-off into the summary.

## Problem

- The stats row rendered `0:50:10239`: time and rate collided and "On goal" wrapped.
- The last 3s of the session said NEXT MINUTE.
- At 0:00 the summary replaced the live view at the old scroll position, so the headline was off screen.
- The live header scrolled away, the timer card pushed reps and pace below the fold, and the minute grid was too small to read (P1).
- The log line's pace (`5→3/min`) disagreed with the table's (`4 → 5 → 3 → 4/min`) (P2).

### Brief items dropped on review

| Item | Why |
|------|-----|
| Coffee button | Already hidden on EMOM routes (`98c21ba`), and EMOM is admin-only |
| Disable the pace stepper in the final minute | It still sets the current minute's reps |
| Release the wake lock on Pause | You pause at the bar, and a sleeping screen hides the paused view |
| Rendered markdown preview | The log line is one table row, so a preview renders nothing useful |
| "Saving…" state | Saving is a synchronous `localStorage` write |
| Contrast fixes | `muted-foreground` on `card` is already ~7:1 in dark mode and ~4.8:1 in light |

The brief asked for `clamp(1.5rem,7vw,2.25rem)`. A 7-character mono value (`0:50:10`, `On goal`) is about 4.2em wide, and with the admin `p-4` and `gap-4` a cell is ~85px at 320px and ~104px at 375px. So 7vw overflows at every phone width. 6vw fits with room to spare.
