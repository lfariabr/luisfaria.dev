# v3.22.1 — Admin Dashboard Redesign

## GitHub Issue

**Issue:** [#319](https://github.com/lfariabr/luisfaria.dev/issues/319) (follows [#318](https://github.com/lfariabr/luisfaria.dev/issues/318), admin shell)

**Title:** `feat(admin): dashboard redesign — needs-attention strip + launch tiles (v3.22.1)`

**Summary:**
The admin dashboard showed all-time project and article counts, the admin's own role, a "coming soon" placeholder and big quick-action cards. It said nothing about Payments, Users, Pins or EMOM. It's now a personal-hub dashboard: a needs-attention strip, then one launch tile per section, built from existing queries only.

## Acceptance Criteria

- [x] The attention strip lists only the agreed rules, each linking to its page; it shows "All clear" when nothing matches
- [x] Six tiles; payment sums grouped per currency (e.g. "AUD 45.00 · USD 10.00")
- [x] Each tile and attention source has its own skeleton, and an inline error with retry; one failing query doesn't blank the page
- [x] Recent Activity placeholder and quick-action cards removed
- [x] Tests: attention rules and their edge cases, window maths, per-currency sums, a single tile failing on its own

## Overview

Second of two admin tickets (the shell shipped in v3.22.0). It's frontend only: the five existing admin queries, plus `featured` added to `PROJECT_FRAGMENT`.

## Changes

### 1. `frontend/src/lib/admin/dashboard.ts` (new)
Pure, tested rules:
- `stalePendingPayments`: `pending` older than 24h
- `recentFailedPayments`: `failed` within the last 30 days
- `recentDraftArticles`: unpublished, `updatedAt` within the last 30 days
- `paymentsThisMonth` (local calendar month): paid count, paid totals per currency, refunded/failed count
- `formatCurrencyTotals`, `countNewSince`, `latestPin` (by visit `date`)
- `toDate`: accepts ISO and epoch-ms strings (User/Article/Project dates have no ISO resolver, so they serialize as epoch ms)

### 2. `frontend/src/app/admin/page.tsx`
Rewritten:
- Five `useQuery` calls, each with `notifyOnNetworkStatusChange` so Retry shows a skeleton
- `AttentionStrip`: payments and articles sources; "All clear" only when both have loaded without errors and nothing matches
- `Tile`: skeleton, inline error with Retry, or stat + detail, plus one action

| Tile | Stat | Detail | Action |
|---|---|---|---|
| Projects | total | featured count | New → `/admin/projects/new` |
| Articles | published | drafts | New → `/admin/articles/new` |
| Payments | paid this month | per-currency sum · refunded/failed | View |
| Users | total | new in last 7 days | View |
| Pins | total | latest place | Open map |
| EMOM | none | none | Start session |

### 3. `frontend/src/lib/graphql/queries/project.queries.ts`
`featured` added to `PROJECT_FRAGMENT` (already `Boolean!` in the schema).

## Decisions

| Decision | Why |
|---|---|
| Failed payments only count for 30 days | `failed` is terminal, so an unbounded rule would never let the strip reach "All clear" |
| Pending payments >24h are unbounded | `pending` only comes from completed checkouts awaiting an async payment (abandoned checkouts aren't stored), so a stuck one is a real problem until it settles |
| "This month" uses the browser's local calendar month | The admin is in Sydney; UTC months would shift payments made on the 1st |
| `now` is fixed per page mount | Stable values across re-renders; a reload refreshes them |
| Queries used directly rather than through `useProjects` etc. | Those hooks don't expose `refetch`, which Retry needs |
