**Epic:** [#388](https://github.com/lfariabr/luisfaria.dev/issues/388)

**Title:** `Epic: v3.28 Log a place in 15 seconds`

Places works end to end, but logging one coffee on an iPhone took about 35 seconds in a 63-second test recording, mostly spent fighting the form: the keyboard hid the header and the button, Safari treated it as a card form, and nothing confirmed the save. This epic makes it fast enough to show off.

Raised on 2026-10-17 from a tester's screen recording and `PLACES_UX_BRIEF.md`.

**Goal:** the same tester, on the same iPhone in Safari, logs a coffee at a place new to the map in **under 15 seconds**, from tapping "Add place" to the pin showing.

## Overview

Follow-up to [v3.26 Places on mobile](v3.26-places-mobile.md) and [v3.27 Places popup](v3.27-places-popup.md). A tester recorded logging one coffee on an iPhone in Safari: about 35 seconds, mostly spent fighting the form. The fixes come from that recording and `PLACES_UX_BRIEF.md`, with these decisions made before starting:

- The brief is input; where it conflicts with the code or the decisions below, the decisions win.
- P0 ships as three PRs, in order, each checked on the iPhone after deploy before the next merges. jsdom cannot show the iOS keyboard or Safari AutoFill.
- No schema change anywhere in the epic.
- Saving focuses the new pin automatically. The toast only confirms; a "View" button would cost a tap against the 15-second goal.
- The sheet is the existing Radix Dialog restructured, with no new dependency.
- "Places near me" is deferred: it adds a billed SKU and a permission prompt, and may not be needed to hit the goal.

## Problem and Changes

### #389 — fix(places): Safari treats the pin form as a card form

#### Problem

On iPhone Safari the add/edit pin form looks like a payment form. The keyboard bar shows the key, card and location AutoFill icons, and QuickType suggests "Amex" while typing in **Spent**. No input in `PinFormDialog.tsx` has a `name` or `autoComplete`, so Safari guesses from the ids and labels (`pin-payment`, "Payment").

#### Work (DOM only, no schema change)

- `autoComplete="off"` on the form and every input, plus `data-1p-ignore` and `data-lpignore="true"`.
- DOM `name`/`id` for the payment field become `paidWith`; the stored and GraphQL field stays `payment`.
- Spent: `$` prefix inside the input, `inputMode="decimal"`, `enterKeyHint="next"`.
- `enterKeyHint="next"` on single-line inputs and `"done"` on the last.
- Label becomes "Paid with" only if the device check still shows AutoFill after the above.

#### Acceptance Criteria

- [ ] iPhone Safari: no AutoFill icons on any field, no "Amex" suggestion on Spent
- [ ] Spent opens the decimal keypad
- [ ] Saved pins keep `payment` unchanged (no migration)

### #390 — fix(places): add-place sheet stays above the iOS keyboard

#### Problem

With the keyboard open on iPhone, the form header ("Add a place" + ✕) scrolls off the top, the "Add place" button hides behind the keyboard, and the page underneath shows through below the sheet. The form is a Radix `Dialog` docked to the bottom with `max-h-[90dvh] overflow-y-auto`, so the whole dialog scrolls as one block.

#### Work

- Restructure the existing Dialog (no new dependency) into a fixed header, a scrolling body and a fixed footer with the CTA.
- Below `sm`: full height (`100dvh`), `overscroll-behavior: contain`. Desktop stays a centred dialog with a max height.
- New `lib/hooks/useKeyboardInset.ts`: listens to `visualViewport` resize/scroll, sets `--kb` = `innerHeight - vv.height - vv.offsetTop`, used as the footer's bottom padding. A focused field scrolls to centre after ~300ms. Listeners removed on unmount.
- `/places` viewport gets `interactiveWidget: 'resizes-content'` for Android Chrome (iOS ignores it, hence the hook).

#### Acceptance Criteria

- [ ] iPhone Safari, any field focused: ✕ and "Add place" stay visible and tappable
- [ ] Nothing from the page behind shows through
- [ ] Esc closes, focus is trapped and returns to the trigger
- [ ] Hook tests: sets and clears `--kb`, removes listeners on unmount

### #391 — feat(places): fly to the new pin and confirm after save

#### Problem

After saving, the sheet closes and you land halfway down the page with no confirmation. Finding the new pin means scrolling and pinching the map. `handleSubmit` in `RelationshipMap.tsx` ignores the pin `createPin` returns, the open popup (`activeKey`) is internal, and there is no map handle.

#### Work (all inside `RelationshipMap`, no new props)

- Keep the pin returned by `createPin` / `updatePin`, after the refetch (`awaitRefetchQueries` already waits).
- Work out its `PlaceGroup.key` and set `activeKey` so its popup opens.
- `<MapFocus>` child uses `useMap()` to `panTo` + `setZoom(17)`; jumps instead of animating under `prefers-reduced-motion`.
- Scroll the map card into view.
- Ring the new timeline row for 1.5s, only if it is in the visible preview.
- Sonner toast "{name} added" / "{name} updated" (no action button).

#### Acceptance Criteria

- [ ] One tap on "Add place" ends with the new pin's popup open and in view, no manual scrolling
- [ ] Same for an edit, with "updated" copy
- [ ] Reduced motion: no smooth pan or scroll

### #392 — feat(places): selected place shows as a name and address chip

#### Problem

After picking a place from autocomplete the search box empties and the form reads `Google place (-33.8727, 151.2244)`.

#### Work (form only, no schema change)

- `PlaceSearch` adds `shortFormattedAddress` to its existing `fetchFields` call (confirm against Google's docs that it stays in the same SKU tier).
- Selected-place chip: **name** + short address + "Change" button that clears the place and focuses the search.
- Editing an existing pin: name + `city, countryCode`.
- Map-picked spot: "Pinned on map" with coordinates rounded to 4 dp.

#### Acceptance Criteria

- [ ] No raw coordinates for a Google place
- [ ] Change restores the search input with focus
- [ ] Test: chip renders without coordinates for a Google place

### #393 — feat(places): tap-to-pick chips for category and payment

#### Problem

Category and Payment are typed by hand (an Input with a `<datalist>`), so a repeat value costs a keyboard and several taps, and Payment gets skipped.

#### Work

- Both become horizontally scrolling `radiogroup` chip rows, ordered by frequency (reuse `suggestionsFrom` in `pinForm.ts`), top 6 plus "+ New".
- "+ New" turns into a text input and keeps what is typed.
- Tapping the selected chip clears it (both fields optional).
- Editing keeps the stored value selected even if it is not in the top 6.
- Seed categories `Eat out`, `Coffee`, `Drinks`, `Groceries`, `Activity` only when there is no history.
- Payment preselects the most recent pin's method, on new pins only.
- Chips are at least 44px tall with visible focus rings.

#### Acceptance Criteria

- [ ] A repeat category and payment is one tap each
- [ ] Tests: select, deselect, create via "+ New", payment preselect on add but not edit

### #394 — feat(places): notes box grows as you type

#### Problem

The notes box is 3 rows and scrolls inside itself after that.

#### Work

- `field-sizing: content` growing from 3 to 8 rows, with a small JS fallback for Safari versions without it.

#### Acceptance Criteria

- [ ] Notes grow with content up to 8 rows, then scroll

### #395 — fix(places): no layout shift on load, hint hides with popup, bigger edit pencil

#### Problem

On load the stat pills show "Loading..." and then reflow from one line to two, and the map card is an empty "Loading relationship pins..." box. The "Tap a pin for details" hint stays visible while a popup is open. The edit pencils (popup and timeline) are about 16-20px, too small to tap.

#### Work

- Fixed-size skeleton stat pills and a map placeholder at the final height, so nothing jumps.
- Hide the "Tap a pin for details" hint while a popup is open.
- Edit pencils in `PlacePopup` and the timeline become 44×44 tap targets (icon size unchanged).

#### Acceptance Criteria

- [ ] No layout shift in the header or map card when pins arrive
- [ ] Hint hidden while a popup is open, back when it closes
- [ ] Pencil hit area 44×44
