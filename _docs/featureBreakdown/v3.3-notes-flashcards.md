## Goal

Add a private logged-in Notes area where users can:

1. Create, edit, delete checkpoint notes
2. View notes in timeline and grouped week/month modes
3. Filter quickly by period and search text

---

## Architecture Summary

### Backend

- New `Note` model and notes GraphQL domain
- User-scoped access via auth context (`context.user.id`)
- Shield rules for auth + note ID shape validation + query filter validation (`validateNoteFilters`)
- Uses graphql-shield's own `and()` combinator (replaces hand-rolled helper)
- Zod validation for note inputs/update/filters (trim-aware, `min(1)` enforced when content provided)
- `noteIdSchema` and `noteFiltersSchema` centralised in `notes.schema.ts`
- `content` field optional throughout (GraphQL type, Zod schema, Mongoose model)
- Note field resolvers serialize Mongoose `Date` → ISO string (prevents "Unknown date" in UI)
- Error handler: already-classified `NotesServiceError` instances are not re-wrapped
- Resolver-side safety:
  - escaped search regex (ReDoS-safe pattern handling)
  - sanitized logs (no raw private search/tag values)
  - unified notes error handling wrapper
- Cookie auth: host-only in dev; `COOKIE_DOMAIN` env var required and applied in production

### Frontend

- New notes GraphQL docs, types, and hooks
- `NoteInput`/`NoteUpdateInput` unified as a single type alias
- `Note.title` and `Note.content` typed as `string | null` (GraphQL nullable)
- New authenticated page: `/notes`
- Create/edit dialogs + delete flow
- Timeline cards + week/month grouping UI
- Note form: content and tags fields hidden (title, date, period, accomplishments, plans only)
- Note card: content and tags display hidden
- Default title derived from `periodType` at both form submit and card render
- Date sent as `${yyyy-MM-dd}T00:00:00.000Z` (avoids off-by-one from `new Date().toISOString()`)
- Route protection for `/notes` in middleware + cookie domain fix enables reliable SSR auth check
- shadcn `Select` for period filter (replaces native `<select>`); sentinel `'ALL'` value avoids Radix empty-string constraint
- Explicit user feedback toasts on create/update failure

---

## Core Behavior

- Notes are private to the authenticated user
- Auto-refresh after create/update/delete via `refetch`
- Default title behavior:
  - weekly notes: `Weekly update`
  - monthly notes: `Monthly update`
- Date rendering is defensive (Mongoose `Date` serialized to ISO string server-side; invalid/missing dates no longer crash UI)
- `/notes` protected at both middleware (SSR) and client-side (`useAuth`) layers
