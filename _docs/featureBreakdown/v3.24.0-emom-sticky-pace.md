# v3.24.0 — EMOM: mid-session pace change sticks

## GitHub Issue

**Issue:** [#343](https://github.com/lfariabr/luisfaria.dev/issues/343)

**Title:** `feat(emom): mid-session reps-per-minute change should persist as the new baseline`

**Summary:**
During the 1,000 pull-up Half-Beast on 11 Oct 2026, lowering the reps per minute with −/+ only held for the minute it was tapped in; the next minute went back to the plan, so the tap had to be repeated every minute of the block. On the 2,000-in-8h attempt the pace will fade 5 → 4 → 3/min in the back half, and re-entering it every minute is friction at the point of most fatigue.

## Acceptance Criteria

- [x] A −/+ tap on the run screen changes the pace from the current minute on, until the next tap
- [x] A pace change survives into the following blocks, including blocks the preset tapers (absolute, not relative)
- [x] −/+ works during the count-in and service stops and applies to the first minute of the next block
- [x] Pace is floored at 1/min and capped at the setup limit (30/min)
- [x] Done vs plan keeps comparing against the configured plan; the panel shows pace and plan side by side
- [x] Minutes run below plan show lighter tints of the signal colour (one step per rep under, capped at three); amber stays for skipped minutes
- [x] The summary's per-block Pace column and the War Room log line show the paces actually run
- [x] A reload resumes with the pace changes intact; snapshots written before this release still load
- [x] The saved setup config is never changed by a mid-session pace change
- [x] Plan tests cover resolution, clamping, tally, block summaries and the log line; a flow test covers pace down, next minute, stop, next block and resume

---

## Overview

The run screen's −/+ now sets a **pace** rather than a one-off count for the current minute. The engine keeps an ordered list of pace changes, each stamped with the block and minute it was made in. The effective pace at any minute is the latest change at or before it, falling back to the configured rate for that block.

## Problem

1. **The adjustment was per minute.** `adjust` wrote a delta keyed by `block-minute`, so a 5 → 3 change lasted one minute. The issue described it as per block; the code never did that, the reporter was tapping − every minute.
2. **No way to set the next block's pace with free hands.** −/+ was disabled outside work minutes, so the decision made during a service stop could not be entered until the block had started.
3. **The summary could not tell a fade from a bad minute.** Every minute below the configured rate was "short" and amber.

## Changes

### 1. Plan math (`lib/emom/plan.ts`)
- `PaceChange { block, minute, rate }` and `paceAt(cfg, paces, block, minute)`: the latest change at or before the minute, else `rateFor`.
- `setPace` appends a change, replacing one made in the same minute, and clamps to the setup limits.
- `repsAt`, `tally`, `extensionPhase` and `blockSummaries` take `paces`. `tally.plan` still sums the configured rate, so the delta measures against the original plan.
- `BlockSummary.paces` lists the paces run in a block; `shortMinutes` now means below the pace in force (skipped minutes). `formatPace` renders `5/min` or `5 → 4 → 3/min`.
- `warRoomLogLine` builds the pace string from the paces run, so a 5-plan paced to 3 logs `5→3/min`.
- Reach-goal extension sizing is unchanged (configured last rate).

### 2. Session engine (`lib/emom/useEmomSession.ts`)
- `Engine`, `SessionView`, `FinishedSession` and the live snapshot carry `paces`.
- `adjust(delta)` resolves the target with `paceTarget`: the current minute in a work phase, otherwise the first minute of the next work phase. It writes a `PaceChange` instead of a per-minute delta.
- `skip` zeroes unstarted minutes against the pace in force, not the configured rate.
- `resume` defaults `paces` to `[]` for old snapshots.

### 3. UI (`components/emom/`)
- **Run:** the panel is now "Pace · from this minute" (or "· next block" during count-in and stops), big number = pace, "plan N · ±d" under it. The section renders during service stops below the checklist. Buttons disable at the floor and cap. Count-in and stop sub-lines use the effective pace.
- **Minute grid:** `data-state` gains `paced`; tint comes from `SIGNAL[color].paced[step]`. Above-plan minutes keep the foreground border.
- **Summary:** Pace column uses `formatPace`.
