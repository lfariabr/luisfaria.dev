# v3.2 — Registration Security Hardening (Turnstile + Rate Limits)

## GitHub Issue + PR

- Issue: [#164](https://github.com/lfariabr/luisfaria.dev/issues/164)
- PR: [#165](https://github.com/lfariabr/luisfaria.dev/pull/165)

---

## Goal

Reduce automated account creation abuse by adding:

1. Cloudflare Turnstile verification on registration
2. Dedicated registration throttling (IP + email)
3. Stronger server-side validation and fail-fast config

---

## Problem

Before this change, `register` relied mostly on input validation and duplicate email checks.  
There was no bot challenge and no dedicated account-creation throttling, which made scripted signups easier.

---

## Solution Summary

### Backend

- Added `captchaToken` to GraphQL + Zod register inputs
- Added Turnstile verification service:
  - `backend/src/services/turnstile.ts`
  - validates payload schema
  - enforces request timeout
  - handles malformed/failed responses safely
- Added registration-specific rate limits in resolver:
  - IP limiter: `register:<clientIp>` (when client IP exists)
  - email limiter: `register-email:<normalizedEmail>`
- Changed order so email throttling only burns after captcha verification succeeds
- Normalized login email (`trim().toLowerCase()`) to match canonical registration behavior
- Config guard:
  - `TURNSTILE_SECRET_KEY` required outside `test`

### Frontend

- Registration page now renders Turnstile widget
- Registration submit requires `captchaToken`
- Submit button disabled until captcha is complete (when site key is configured)
- Added widget cleanup on unmount (`turnstile.remove`)
- Aligned password rule/error text to minimum 8 characters
- Auth context updated to send `captchaToken` in register mutation

---

## Security Behavior

- Missing/invalid/expired captcha token blocks registration
- Abusive registration patterns are throttled by IP and per-email buckets
- Backend secret key never exposed to client (`TURNSTILE_SECRET_KEY` server-side only)
- Frontend uses public site key only (`NEXT_PUBLIC_TURNSTILE_SITE_KEY`)
- Fail-fast startup prevents misconfigured prod deployments (missing Turnstile secret)

## Local Setup

Add keys:

- `backend/.env` → `TURNSTILE_SECRET_KEY=...`
- `frontend/.env.local` → `NEXT_PUBLIC_TURNSTILE_SITE_KEY=...`

Run:

```bash
cd backend && npm run dev
cd frontend && npm run dev
```

> Note: on localhost, Turnstile may auto-pass quickly (showing immediate success) depending on risk scoring and key mode. This is expected.
