## GitHub Issue

**Epic:** [#350](https://github.com/lfariabr/luisfaria.dev/issues/350)

**Title:** `Epic: v3.25 Places — revive relationship pins as a shared couple's map`

**Summary:**
Pins shipped in v3.6 as an admin-only map seeded from a gitignored script and has not grown since April 2026. The only way to add a pin is the script or a raw GraphQL call. This epic makes Places a private shared memory of places visited together: admin and partner add and edit pins from the page, and a committed importer catches the map up from the spreadsheet.

Decided in a grilling session on 2026-10-14. Closes the open question in [#337](https://github.com/lfariabr/luisfaria.dev/issues/337); supersedes [#208](https://github.com/lfariabr/luisfaria.dev/issues/208).

## Acceptance Criteria

- [ ] A PARTNER can add a place from a phone; an ADMIN can edit and delete it
- [ ] The April–October 2026 backlog is imported from the sheet CSV with one command, re-runnable without duplicates
- [ ] Nothing in the UI says "Relationship Map"; `/relationship` and `/admin/relationship` redirect to `/places`
- [ ] All stored amounts are positive; the API rejects negatives
- [ ] CONTEXT.md has a `Pin` term with resolving `_Lives in_` paths

---

## Overview

Places is the second iteration of the v3.6 relationship pins map. v3.6 hardened a read-only admin map; v3.25 turns it into something two people use. The work is ordered so the data arrives first (importer), then the API can change it (backend), then the page can (frontend), then the page gets its real name (surface), then the glossary records it.

## Problem

- The feature was abandoned because adding a pin required running a gitignored script against a finance export. Last data: April 2026.
- The script already met every acceptance line in #208 but lived only on one disk, so the issue sat open for five months.
- PARTNER (added in #273) can look but not touch.
- Two routes render one component under two shells, and the name "Relationship Map" reads like a CRM feature.
- Amounts are stored negative (finance-export convention) and the UI takes the absolute value everywhere.

## Decisions

| Question | Decision | Why |
|---|---|---|
| Purpose | Private couple's memory tool, ADMIN + PARTNER | Everything from v3.6 (noindex, home marker, PARTNER role) already says so; sharing has no reason yet |
| #208 | Commit the script stripped, `--input` mandatory, close via #351 | 20 minutes, real commit, importer stays useful for bulk loads |
| Next iteration | In-app create/edit/delete | The feature is abandoned because adding a pin is painful; UX and analytics only polish a static dataset |
| Who writes | PARTNER creates and edits, ADMIN deletes | A shared memory one person can add to is a half-feature; admin-only delete is a cheap safety net |
| Surface | One route, `/places`, redirects from both old paths | The admin shell is for running the site, and the partner should never see it |
| Coordinates | Places Autocomplete, tap-on-map fallback, store `placeId` | Phone-friendly, clean names, grouping by place later |
| Category / payment | Free text with suggestions from existing values | One value each so far; an enum is premature, typing by hand is how it gets abandoned again |
| Amount sign | Positive, migrate existing, Zod rejects negatives | One convention at the boundary; UI already uses `Math.abs` |
| Uniqueness | Drop the unique index, keep a plain one | It existed for script idempotency; the importer can match on the triple without it |
| Source of truth | The app, from now on; the sheet import is a catch-up | Two records means double entry and near-duplicates from renamed places |
| Sheet access | Download CSV, `--input ./pins.csv` | Publish-to-web makes spending public; Sheets API costs a credential to save a download |
| Importer match key | place + date + amount | With the app as record, the import only meets its own earlier rows |
| Currency | AUD only, no field | `countryCode` can backfill it later |
| Edit / delete | Partial update, hard delete, no undo | Delete is admin-only already |
| Add flow | Sheet on mobile, dialog on desktop, same component for edit | One component, small tests; long-press-to-pin comes with map UX |

## Changes

### 1. Importer (`backend/scripts/seed-pins.ts`) — #351

- Remove `defaultRawPins`; `--input` mandatory
- CSV input with fixed headers; JSON still accepted
- Store `placeId` from the Geocoding response
- Un-ignore the script; ignore `backend/scripts/pins*.csv|json`

CSV template:

```csv
date,placeName,amount,category,payment,city,countryCode,notes
2026-04-26,Corner Cafe,42.50,Eat out,Amex,Sydney,AU,
2026-05-03,Harbour Bistro,18.00,Eat out,Amex,Sydney,AU,anniversary
```

`date`, `placeName`, `amount` required; `lat`,`lng` optional columns skip geocoding for that row.

### 2. Backend (`backend/src/{schemas/types/pinTypes.ts,resolvers/pins/,validation/,models/Pin.ts}`) — #352

| File | Change |
|---|---|
| `schemas/types/pinTypes.ts` | `updatePin`, `deletePin`, `PinUpdateInput`, `placeId` |
| `resolvers/pins/mutations.ts` | update (partial) and delete resolvers via `withPinErrorHandling` |
| `validation/shield.ts` | create/update for ADMIN or PARTNER; delete ADMIN only |
| `validation/schemas/pin.schema.ts` | `amount > 0`, optional `placeId`, update schema |
| `models/Pin.ts` | `placeId` indexed; unique index becomes plain |
| `scripts/migrate-pins.ts` + `src/utils/pinMigration.ts` | flip amounts to absolute value, drop the old unique index, `--dry-run`, idempotent |

### 3. Frontend form (`frontend/src/components/relationship/`, `lib/graphql/mutations/`) — #353

- `PinFormSheet`: Sheet below `md`, Dialog above; create and edit
- Places Autocomplete via `useMapsLibrary('places')`; "Pick on map" fallback
- `datalist` suggestions for category and payment
- Edit action on InfoWindow and timeline; Delete (ADMIN) behind `AlertDialog`
- `.env.example`: browser key needs the Places API enabled

### 4. Surface (`frontend/src/app/places/`, `proxy.ts`, nav) — #354

- `app/relationship` → `app/places`; delete `app/admin/relationship`
- 308 redirects from both old paths; role gate on `/places`
- "Places" in header, admin nav, dashboard tile, title; partner copy on users page
- Subtitle drops "this year"

### 5. CONTEXT.md — #355

`### Places` section with `Pin`, `Places map`, `Importer` and `_Lives in_` paths.
