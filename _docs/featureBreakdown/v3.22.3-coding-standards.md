## Overview

Mechanical rules go to the linter, judgement calls go to one short file the review reads by name, and the stale second source of truth is removed.

## Problem

1. **Review caught what lint should.** The `createErrorHandler` / raw `GraphQLError` rule was written in prose in two files and still breached; prose rules are read by the implementation agent under the most context pressure.
2. **Two architecture sources of truth.** `CLAUDE.md` called `copilot-instructions.md` authoritative. That file listed NextAuth.js (never in the code), Next.js 14 (installed: 16), "8 test suites, 28+ tests" (now 20 / 298), and a resolver tree missing five domains.
3. **`.DS_Store` noise.** Four were tracked, so every Finder visit dirtied the tree.

## Changes

### 1. ESLint rule (`backend/eslint.config.mjs`)
`no-restricted-syntax` on `NewExpression[callee.name='GraphQLError']`, error level. Off for the error infrastructure (`utils/errors/**`) and for `validation/shield.ts` + `validation/middleware.ts`, which return errors by design. Off by name for three legacy rate-limit sites (`middleware/rateLimiter.ts`, `utils/applyRateLimit.ts`, `resolvers/screams/mutations.ts`) with a comment pointing at the rate-limiting work, where an `Errors.rateLimited` factory should replace them.

### 2. `CODING_STANDARDS.md`
Seven short sections: errors, validation and input, rate limiting, logging, frontend, tests, change hygiene. Each line is a judgement call no guardrail substitutes for. Carries over the live rules from the copilot file plus three learned since: `force-dynamic` on `fetchGql` pages, theme tokens over raw palette classes, FABs render through `FabStack`.

### 3. `copilot-instructions.md` deleted
`CLAUDE.md` monorepo list points at `CODING_STANDARDS.md`; its Code Style section defers to ESLint and the standards file. CI `paths-ignore` entries removed.

### 4. `.DS_Store`
Four files untracked; `.DS_Store` added to `.gitignore`.
