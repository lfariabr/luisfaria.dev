## Overview

Rate limiting is now one module. A call site names a Rate limit and passes a Subject; the numbers, Window, visibility and failure mode live in one list.

```
backend/src/rateLimiting/
├── rateLimits.ts   # the list: limit per Subject kind, Window, visibility, failure mode
├── subject.ts      # Subject.user / .email / .ip; missing → unknown
├── counter.ts      # the Redis Lua counter (throws when Redis is down)
├── consume.ts      # consume(name, subject): count, decide fail open/closed, log
├── errors.ts       # RateLimitExceeded, RateLimitUnavailable
├── graphql.ts      # enforceRateLimit + toGraphQLError: domain errors → Errors.*
└── index.ts
```

## Changes

### 1. The module
- `consume(name, subject)` returns `{ limit, remaining, resetTime }` or throws `RateLimitExceeded` / `RateLimitUnavailable`. No `graphql` dependency.
- `enforceRateLimit(name, subject)` is `consume` for resolvers: a Visible rate limit becomes `Errors.rateLimited`, a Silent one `Errors.rateLimitedSilently(message)`, an outage on a fail-closed rate limit `Errors.unavailable()`.
- Subject kinds are type-checked per rate limit (`consume('goggins', Subject.ip(...))` does not compile).
- Logs only over-limit (`warn`), fail open / fail closed (`error`) and missing Subject (`warn`). Emails are never logged.
- Keys: `rl:<rateLimit>:<subjectKind>:<id>`.

### 2. Error factories (`utils/errors`)
`Errors.rateLimited({ limit, remaining, resetTime, resetIn? })`, `Errors.rateLimitedSilently(message)`, `Errors.unavailable(message?)`; `ErrorCodes.RATE_LIMITED`. `TOO_MANY_REQUESTS` stays: APOD uses it for NASA's upstream rate limit, which is not a visitor's Rate limit.

### 3. Call sites
| Call site | Before | After |
|---|---|---|
| `askQuestion` | `middleware/rateLimiter.ts`, config | `enforceRateLimit('chatbot', Subject.user)` |
| `getTodaysApod` | `applyRateLimit`, `apod:today:<user>` / `apod:today:ip:<ip>` | `enforceRateLimit('apod', Subject.user \| Subject.ip)` |
| `getApodByDate` | `applyRateLimit`, `apod:date:<user>` | `enforceRateLimit('apod', Subject.user)` |
| `activateGogginsMode` | direct `rateLimiter.limit`, raw `GraphQLError` | `consume('goggins', Subject.email)` + `Errors.rateLimited` with `resetIn` (until #340) |
| `register` (IP) | direct, skipped when no IP | `enforceRateLimit('registerByIp', Subject.ip)` |
| `register` (email) | direct, `badInput` | `enforceRateLimit('registerByEmail', Subject.email)` |
| `/health/ready` | direct, 429 with `resetTime` | `consume('healthReady', Subject.ip)`, 429 with no numbers |

### 4. GraphQL schema
One `RateLimitInfo` (`schemas/types/rateLimitTypes.ts`): `limit`, `remaining`, `resetTime`, plus `allowed` / `resetIn` as nullable `@deprecated` fields for Goggins until #340. The scream and rateTest definitions are gone.

### 5. Deleted
`services/rateLimiter.ts`, `middleware/rateLimiter.ts`, `utils/applyRateLimit.ts`, `gogginsRateLimiter`, `testRateLimit` (query, resolver, types, Shield rule), `RATE_LIMIT_*` (config, required-env list, `.env.example`, both compose files, `backend/` compose files, CI), the ESLint rate-limit override block.

### 6. Docs
`CLAUDE.md`: Rate Limiting section points at the module; the resolver-pattern example now matches `createErrorHandler`'s real signature. Lint warning cap ratcheted 123 → 117 (deleted files carried six `any`s).
