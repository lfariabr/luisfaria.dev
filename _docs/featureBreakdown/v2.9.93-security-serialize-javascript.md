# v2.92.1 — Security: Patch serialize-javascript RCE (Dependabot #29)

## GitHub Issue

**Title:** `security: upgrade serialize-javascript to 7.0.3 (CVE RCE via RegExp.flags)`

**Description:**
Dependabot alert #29 flagged `serialize-javascript` <= 7.0.2 for a code injection vulnerability (RCE via `RegExp.flags` and `Date.prototype.toISOString()`). The patched version is 7.0.3.

A direct `npm install` is blocked because `terser-webpack-plugin@5.3.16` (a transitive dep of `webpack` → `next`) declares `serialize-javascript: ^6.0.2`, causing a version conflict. The fix is to use npm's `overrides` field to force `7.0.3` globally.

**Acceptance criteria:**
- [ ] `frontend/package.json` contains `"overrides": { "serialize-javascript": "7.0.3" }`
- [ ] `npm ls serialize-javascript` from `frontend/` shows all instances at `7.0.3`
- [ ] `npm audit` reports 0 vulnerabilities
- [ ] `npm run build` completes without errors
- [ ] All frontend tests pass

---

## Overview

Patches a Remote Code Execution vulnerability in `serialize-javascript` by forcing version `7.0.3` via npm's `overrides` mechanism. The override is safe because v7.0.3 is a pure security patch with no API changes relative to v6.

## Problem

- `serialize-javascript` <= 7.0.2 has a known RCE via malformed `RegExp` and `Date` serialization
- Direct upgrade blocked by `terser-webpack-plugin@5.3.16`'s `^6.0.2` semver constraint
- Vulnerability exposed in the production frontend build pipeline

## Dependency Chain

```
next ^16.1.6
  └─ webpack 5.105.1
     └─ terser-webpack-plugin 5.3.16
        └─ serialize-javascript ^6.0.2  ← was 6.0.2, forced to 7.0.3
```
