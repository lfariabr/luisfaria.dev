# v2.92 — SEO Takeover v1

## GitHub Issue

**Title:** `feat: seo-takeover-v1 — full-site SEO hardening with SSR migration, structured data, and CI audit gate`

**Description:**
Following the v2.91 SEO monitor agent, a deeper audit exposed structural gaps: pages with no canonical, missing JSON-LD, client-side data fetching that blocked crawlers, admin/auth routes exposed to indexing, and no legal pages linked in the footer. This issue tracks the comprehensive SEO overhaul across all public routes.

**Deliverables:**
- Per-route metadata (canonical, OG, Twitter) for `/work`, `/projects`, `/articles`, `/chatbot`, `/admin`, `/(auth)`
- Migrate `/work`, `/projects`, `/articles` listing pages from CSR to SSR via `fetchGql`
- Replace CSS background images on project/article cards with semantic `<Image>` elements
- Add `/privacy` and `/terms` legal pages
- `sanitizeJsonLd` helper to safely embed structured data
- `buildDescription`, `resolveOgImage` helpers centralized in `frontend/src/lib/seo/metadata.ts`
- Enrich structured data on home page (Person + WebSite + Organization) and listing pages (CollectionPage + ItemList)
- Harden sitemap with correct dates and static route policy
- Extend `seo-audit.ts` with canonical, noindex, internal link checks
- Block Docker build in CI until SEO audit passes

**Acceptance criteria:**
- [ ] All public routes have `<title>`, `<meta description>`, `og:title`, `og:image`, `canonical`, and `application/ld+json`
- [ ] Admin, login, and register routes emit `noindex, nofollow`
- [ ] `/privacy` and `/terms` return 200 and appear in sitemap
- [ ] `seo-audit.ts` passes at ≥ 80% overall score
- [ ] CI `docker-build` is blocked until `seo-audit` gate passes
- [ ] No raw error messages exposed to users on SSR pages

---

## Overview

Comprehensive SEO hardening across the full Next.js frontend. Migrates data-fetching for three listing pages from Apollo CSR to server-side `fetchGql`, adds per-route metadata with canonical and structured data, introduces legal pages, centralizes SEO helpers, and gates CI Docker builds on a live SEO audit score.

## Problem

- Listing pages (`/work`, `/projects`, `/articles`) were rendered client-side — crawler saw empty HTML
- No canonical tags on any route; risk of duplicate-content penalties
- Admin and auth routes (`/admin`, `/login`, `/register`) were indexable
- JSON-LD on home page used raw `JSON.stringify` — XSS vector via `</script>` injection
- No `/privacy` or `/terms` pages, despite footer links pointing to them (404s)
- SEO audit script only checked title, description, og:title, og:image, json-ld — no canonical or noindex verification
- CI had no gate to prevent shipping an SEO regression to production

### Frontend — SSR Migration

Three listing pages migrated from Apollo Client (CSR) to `fetchGql` (server-side):

- `frontend/src/app/work/page.tsx` — fetches projects + articles in parallel, passes to `WorkTabsContent`
- `frontend/src/app/projects/page.tsx` — fetches projects, renders `ProjectCard` grid
- `frontend/src/app/articles/page.tsx` — fetches articles, renders article list

All pages use generic error messages on failure (no internal stack leakage).

> **Note (open issue):** Both pages export `dynamic = 'force-dynamic'` while also passing `revalidate: 3600` to `fetchGql`. These are contradictory — `force-dynamic` disables all ISR caching. Should pick one strategy before merge: either remove `dynamic` export (enable ISR) or remove `revalidate` option (keep always-fresh).

### Frontend — Image Handling

`ProjectCard.tsx` replaced CSS `background-image` with semantic `<Image>` from `next/image` — crawlable, LCP-friendly, alt-text supported.

### Frontend — Legal Pages

- `frontend/src/app/privacy/page.tsx` — Privacy Policy stub
- `frontend/src/app/terms/page.tsx` — Terms of Service stub
- Both added to `frontend/src/app/sitemap.ts` with static `lastModified`

### Frontend — SEO Helpers (`frontend/src/lib/seo/metadata.ts`)

| Helper | Purpose |
|--------|---------|
| `sanitizeJsonLd(data)` | `JSON.stringify` + escape `<`, `>`, `&` to prevent script injection |
| `buildDescription(primary, fallback, max)` | Strip markdown, truncate to 160 chars |
| `resolveOgImage(imageUrl?)` | Returns image URL or fallback to `/og-default.png` |

### Frontend — `fetchGql` (`frontend/src/lib/graphql/fetchGql.ts`)

- Added `resolveGraphqlUrl()` to handle bare hostnames — defaults to `http://` prefix (open issue: should be `https://` to avoid accidental security downgrade in production)
- Added `revalidate` option to `FetchGqlOptions`
- Wrapped with `React.cache()` for server-side request deduplication

### Admin Layout Refactor

Extracted client-side auth logic from `app/admin/layout.tsx` into `AdminLayoutClient.tsx`. Server layout is now a thin wrapper with noindex metadata; client component handles role-based redirect and sidebar rendering. Spinner guard (`loading || !isAuthenticated || !isAdmin`) prevents admin content flash for unauthorized users.

### Backend — SEO Audit (`backend/scripts/seo-audit.ts`)

Extended with three new check types:

| Check | What It Validates |
|-------|------------------|
| `checkCanonical(html, url)` | Canonical `<link>` present and matches the expected URL |
| `checkNoIndex(html)` | `<meta name="robots" content="noindex">` present |
| `checkNoFollow(html)` | `<meta name="robots" content="nofollow">` present |
| Restricted URL audit | Verifies `/login`, `/register`, `/admin` all have `noindex + nofollow` |
| Internal link audit | Verifies key routes (`/`, `/work`, `/projects`, `/articles`, `/chatbot`, `/privacy`, `/terms`) return HTTP 200 |

### CI — SEO Audit Gate (`.github/workflows/ci.yml`)

- New `seo-audit` job runs after `build-check` on push events
- `docker-build` now `needs: [backend-test, frontend-test, seo-audit]` — SEO regression blocks release
- 12-minute timeout; runs `npx ts-node backend/scripts/seo-audit.ts`

> **Open issue:** Audit job runs on all `push` events, not just master — feature branches will hit the production URL. Should add `github.ref` branch guard to restrict to master/main.
