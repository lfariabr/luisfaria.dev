# v3.19 — Admin EMOM Tracker

## GitHub Issue

**Issue:** [#307](https://github.com/lfariabr/luisfaria.dev/issues/307)

**Title:** `Admin EMOM tracker for long pull-up sessions (/admin/emom)`

**Summary:**
Long pull-up sessions (50-minute EMOM blocks at 5 reps/min with 10-minute service stops, building to 2,000 in 8 hours) were timed with a generic stopwatch next to the bar. This adds an admin-only page that runs the full cycle, shows a go signal you can read from the bar, and logs every session in the browser.

## Overview

A gym-screen timer for EMOM pull-up sessions: setup → count-in → work blocks with a go signal on every minute → service stops → summary with a War Room log line. Validated as a single-file prototype (three iterations) before the port to Next.js.

## Problem

1. **A stopwatch has no idea of the plan.** It can't say which block you're in, how many reps this minute, or when the next service stop is.
2. **Hard to read from the bar.** The start of each minute needs a signal visible across the room, not small digits.
3. **The 2,000 plan slows down late.** Hours 5–8 drop to 4/min, which leaves the session short of the goal unless time is added.
4. **Logging happened after the fact**, from memory, into the War Room.

## Changes

### 1. Plan math (`lib/emom/plan.ts`)
Pure functions with no React: presets, per-block rates, `buildPhases` (count-in → work → stop → … → optional extra block), `tally` (a minute counts once its signal window has passed), `extensionPhase` (reach-goal mode adds minutes at the last block's pace when reps fall short), `blockSummaries` and `warRoomLogLine`.

### 2. Session engine (`lib/emom/useEmomSession.ts`)
A hook that owns the clock (100ms tick, `Date.now` deltas so a throttled tab catches up), pause, skip, rep adjustments, 3-2-1 beeps (Web Audio), screen wake lock, and a snapshot to `localStorage` every minute, on pause/adjust, and on `pagehide`.

### 3. Browser storage (`lib/emom/storage.ts`)
`emom:config`, `emom:log`, `emom:live`. Every read and write is wrapped so blocked storage never stops the timer. No backend changes: MongoDB was considered and dropped for v1.

### 4. UI (`components/emom/`)
- **Setup:** presets, steppers, a reps-per-minute stepper for each block, finish line (end of plan / reach goal), session map, the cycle as a timeline, go-signal options with a live preview, and the training log with the month total (2,000 goal).
- **Run:** a large minute countdown, a solid full-screen go signal (no blinking) or a blinking clock panel, −/+ for reps this minute, a minute grid, a service-stop checklist, pause/fullscreen/end (two taps to end), and keyboard shortcuts.
- **Summary:** totals, a per-block table, notes, and a copyable War Room log line.
- Uses the site's theme tokens, so it follows light and dark mode.

### 5. Review follow-up — skip credited unstarted minutes
PR review (CodeRabbit) caught that skipping a work block (`N`) moved the clock to the end of the block, and `tally` then credited every minute in it. One skip at minute 2 of a 50-minute block added ~240 reps to the summary, the War Room line and the month total. In reach-goal mode the inflated count also stopped `extensionPhase` from adding the minutes still needed.

Fix: `skip` now writes a `-rate` adjustment for every minute not yet started (the current minute counts as not started until its signal window passes), then persists. Skipped minutes show amber in the minute grid, and reach-goal mode adds the time back. Skipping a service stop or the count-in is unchanged. A regression test skips at minute 2 and expects 5 reps. The same test exposed a crash in the keyboard handler when an event target isn't an element, now guarded with `instanceof Element`.
