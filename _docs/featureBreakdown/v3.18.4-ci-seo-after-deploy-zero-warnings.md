## Overview

Two CI hygiene fixes: audit production after it's deployed, and hold the frontend to zero lint warnings.

## Problem

1. **SEO gate race.** `seo-audit` only needed `build-check`, so it ran alongside `Deploy to Production` against `https://luisfaria.dev`. On the #298 merge it hit `fetch failed` / timeouts on every route (65% vs an 80% threshold) while every route returned 200 seconds later. It's `continue-on-error`, so nothing was blocked, but runs went red for no reason. When it did pass, it was auditing the previous build.
2. **67 warnings.** #300 gated CI on errors only.

## Changes

### 1. SEO gate after deploy
`seo-audit` now has `needs: [deploy]`. The deploy job ends with health checks, so the audit runs against the new build once it's confirmed up. If the deploy fails, the audit is skipped, which is correct: there's nothing new to audit.

### 2. Zero warnings, enforced
`"lint": "eslint . --max-warnings 0"`. Confirmed that a single new warning exits 1.
