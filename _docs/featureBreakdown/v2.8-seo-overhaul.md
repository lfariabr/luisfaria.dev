# v2.8 — SEO Overhaul

## Overview

Comprehensive SEO overhaul for luisfaria.dev addressing four critical gaps: client-side rendered content pages invisible to crawlers, identical generic metadata across all pages, a static sitemap missing all dynamic content URLs, and no structured data (JSON-LD) for rich search results.

## Problem

- **Empty HTML shells**: Article and project detail pages were `'use client'` components — crawlers received a loading spinner instead of content
- **Generic metadata**: Every page shared the same `<title>` and Open Graph tags ("Luis Faria | Senior Software Engineer"), so sharing an article on social media showed no article-specific info
- **Incomplete sitemap**: Only 4 static routes listed; all individual articles and projects were missing
- **No structured data**: No JSON-LD markup, preventing rich results (article cards, breadcrumbs) in search engines
- **Static robots.txt**: No admin/auth route exclusions

## Changes

### 1. Server-Side GraphQL Fetch Utility

**New file:** `frontend/src/lib/graphql/fetchGql.ts`

- Plain `fetch()` wrapper for calling GraphQL from Server Components (no Apollo dependency)
- Uses Next.js ISR caching (`next: { revalidate }`) — default 1 hour
- Wrapped with `React.cache()` to deduplicate calls between `generateMetadata()` and page render within a single request

**New file:** `frontend/src/lib/graphql/queries/server.queries.ts`

- Plain string GraphQL queries (not `gql` tagged templates) for: `ARTICLE_BY_SLUG_QUERY`, `PUBLISHED_ARTICLES_QUERY`, `PROJECT_BY_SLUG_QUERY`, `PROJECTS_QUERY`

### 2. Article Detail Page → Server Component

**New file:** `frontend/src/components/articles/ArticleContent.tsx`

- Extracted rendering logic into a `'use client'` component receiving `article` as a prop (needed for `MarkdownMessage`)

**Rewritten:** `frontend/src/app/articles/[id]/page.tsx`

| Before | After |
|--------|-------|
| `'use client'` with `useArticleBySlug` hook | Async Server Component with `fetchGql()` |
| No `generateMetadata()` | Dynamic title, description, canonical URL, OG article tags, Twitter card |
| No structured data | `Article` + `BreadcrumbList` JSON-LD |
| Loading spinner visible to crawlers | Full HTML rendered server-side |

### 3. Project Detail Page → Server Component

**New file:** `frontend/src/components/projects/ProjectContent.tsx`

- Same extraction pattern as articles

**Rewritten:** `frontend/src/app/projects/[id]/page.tsx`

| Before | After |
|--------|-------|
| `'use client'` with `useProjectBySlug` hook | Async Server Component with `fetchGql()` |
| No metadata | Dynamic title, description, canonical, OG, Twitter card |
| No structured data | `SoftwareApplication` + `BreadcrumbList` JSON-LD |

### 4. Listing Page Metadata

**New files:** `frontend/src/app/articles/layout.tsx`, `frontend/src/app/projects/layout.tsx`

- Export static `metadata` objects with page-specific titles, descriptions, canonical URLs, and Open Graph tags
- Route layouts used because the listing pages are `'use client'` components (can't export metadata from client components)

### 5. Updated TypeScript Types

**Modified:** `frontend/src/lib/graphql/types/article.types.ts`
- Added: `publishedAt?: string`, `categories?: string[]`

**Modified:** `frontend/src/lib/graphql/types/project.types.ts`
- Added: `liveUrl?: string`, `featured?: boolean`, `order?: number`

### 6. Dynamic Sitemap

**Rewritten:** `frontend/src/app/sitemap.ts`

| Before | After |
|--------|-------|
| Synchronous, 4 static routes | Async, fetches all published articles and projects |
| No individual content URLs | Generates `/articles/{slug}` and `/projects/{slug}` for every item |
| Hardcoded `lastModified` | Uses `updatedAt` from database |

**Deleted:** `frontend/public/sitemap.xml` — stale static file that overrode the dynamic `sitemap.ts` (Next.js serves `public/` files first)

### 7. Homepage Structured Data

**Modified:** `frontend/src/app/page.tsx`

- Added `Person` JSON-LD (name, jobTitle, url, sameAs social links)
- Added `WebSite` JSON-LD (name, url, description)

### 8. Dynamic robots.txt

**Deleted:** `frontend/public/robots.txt`

**New file:** `frontend/src/app/robots.ts`
- Disallows: `/admin/`, `/login`, `/register`, `/api/`
- Allows everything else
- Points to sitemap at `https://luisfaria.dev/sitemap.xml`

### 9. Fallback OG Image

**New file:** `frontend/public/og-default.png`
- 1200x630 branded image with site name and tagline
- Used as fallback for pages/articles without a custom image

## Next Steps

### High Priority
- **Convert articles listing page to Server Component**: The `/articles` page is still `'use client'` — convert it to SSR so the article list HTML is crawlable, not just the detail pages
- **Convert projects listing page to Server Component**: Same as above for `/projects`
- **Replace fallback OG image**: The auto-generated `og-default.png` is basic — design a polished branded version (1200x630) in Figma or similar
- **Add `publishedAt` field to backend Article model**: Currently using `createdAt` as the publish date; a dedicated `publishedAt` allows backdating and scheduling

### Medium Priority
- **Dynamic OG images with `next/og`**: Use Next.js `ImageResponse` API to generate per-article/project OG images on the fly with title text overlaid on a branded template
- **Add `generateStaticParams()`**: Pre-render the most popular article/project pages at build time for faster TTFB, while keeping ISR for new content
- **Canonical URLs for paginated listings**: If article/project listings get pagination, add `rel="canonical"` and `rel="next/prev"` links
- **Hreflang tags**: If the site adds Portuguese content, add `hreflang` alternate links

### Low Priority
- **Google Search Console submission**: Submit the new sitemap and request indexing of key pages
- **Performance monitoring**: Track Core Web Vitals (LCP, CLS, INP) for the new server-rendered pages vs the old client-rendered ones
- **FAQ/HowTo structured data**: If articles contain how-to content, add `HowTo` JSON-LD for enhanced SERP features
- **Author page with `ProfilePage` JSON-LD**: Dedicated `/about` page with full structured data for Google's knowledge panel
