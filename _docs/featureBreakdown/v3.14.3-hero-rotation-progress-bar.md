## Overview

UX polish for the rotating hero headline (v3.14). Added a slim, decorative progress bar under the
lens pill that fills left→right over each rotation interval (~2.95s), giving the viewer a sense of
rhythm and a cue that the clause is about to change.

## Problem

The headline rotated with no indication of timing, so the swap could feel abrupt/surprising. A
fill indicator makes the motion read as intentional and "alive".

## Changes

- **`lib/hooks/useRotatingText.ts`** — now returns `{ index, isRotating }` (was just `index`).
  `isRotating` is `false` on SSR/first paint and under `prefers-reduced-motion`, and only flips
  `true` once the timer is actually running. This lets the bar render *only* when rotation is live,
  avoiding a misleading/animating bar when motion is reduced and avoiding hydration mismatch.
- **`components/sections/HeroHeadline.tsx`** — pill + bar grouped in one centered flex column
  (`gap-2.5`). The bar is a 0.5px-tall, 3rem-wide emerald track; the inner fill runs the
  `hero-progress` keyframe (`scaleX(0)→scaleX(1)`, `origin-left`, linear) over `ROTATE_MS`, and is
  re-keyed on `index` so it restarts cleanly each frame. `ROTATE_MS` is a shared constant passed to
  the hook so the fill duration and the rotation interval stay in sync. Decorative (`aria-hidden`).
- **`app/globals.css`** — one `@keyframes hero-progress` (GPU-cheap transform; no width animation).

No layout shift, no new dependency, SEO/a11y unchanged (canonical `<h1>` untouched; bar is
`aria-hidden`).
