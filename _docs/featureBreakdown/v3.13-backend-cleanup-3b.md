## Overview

Final Phase 3 cleanup item: the last two resolvers throwing raw errors now use the shared `Errors.*` factories, matching the documented pattern (CLAUDE.md).

## Changes

### `screams/mutations.ts`
- The `BAD_USER_INPUT` raw `GraphQLError` → `Errors.badInput('Invalid email address')` (same code + message).
- The rate-limit error **intentionally stays** a structured raw `GraphQLError` — it carries metadata (`limit`, `remaining`, `resetTime`, `resetIn`) and already uses the unified `RATE_LIMITED` code, consistent with `applyRateLimit`.

### `resend/mutations.ts`
- `new Error(...)` → `Errors.internal(...)` (proper `INTERNAL_SERVER_ERROR` GraphQL code instead of an unwrapped JS error).
- Added a guard so an already-GraphQL error isn't double-wrapped; stopped stringifying raw service errors to the client.

## Out of scope
Consolidating the two rate-limit utility *functions* (`rateLimit` middleware vs `applyRateLimit`) — different call styles, low value, deferred.
