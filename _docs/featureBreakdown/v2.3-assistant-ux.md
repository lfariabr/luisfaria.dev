# AI Assistant Rebuild Plan

## Goals
- ✅ Make the AI assistant feel like a flagship feature with a bold, legible layout rather than an embedded chat box.
- ✅ Surface rate limiting as a first-class UX element with proactive guidance (remaining quota, reset timing, rationale).
- ⏱️ Introduce a side “Mode Toggler” (inspired by Goggins Mode) so users can switch personalities/contexts without leaving the flow.
- ⏱️ Improve trust by clarifying authentication state, data usage, and assistant knowledge sources.
- ⏱️ Instrument the experience for better observability (rate-limit hits, mode usage, drop-offs).

## Experience Pillars
1. **Split Workspace Layout** – Persistent info rail (profile, rate limit, modes) + immersive conversation canvas.
2. **Transparent Rate Limiting** – Visual meter, countdown, historical usage hints, and contextual CTAs when exhausted.
3. **Mode Control Surface** – Inline selector for “Classic Assistant”, “Goggins Mode”, future personas; each with description and gating.
4. **Guided Interactions** – Hero copy, suggested prompts, empty states, and error recovery flows that explain next steps.
5. **Operational Readiness** – Telemetry + UI hooks to expose when/why limits trigger so we can iterate quickly.

## Issue List

### 1. Re-architect page layout into dual-pane workspace
- **Problem**: Current `/chatbot` page stacks hero, alerts, and chat vertically, so rate-limit info and persona context quickly scroll away @frontend/src/app/chatbot/page.tsx#214-417.
- **Plan**: Create a responsive grid with: (a) left info rail (hero, persona cards, auth state, rate limit) that stays visible; (b) right chat canvas with sticky composer.
- **Scope**:
  - New layout container + CSS grid utilities.
  - Refactor hero + explanation cards into reusable components.
  - Ensure mobile collapses info rail into accordions/tabs.
- **Acceptance**: Rate-limit + mode info remain visible during scrolling on desktop and accessible via toggles on mobile.

### 2. Rate-limit clarity system
- **Problem**: Users only see remaining quota in hero cards and occasional alerts; countdown appears only after hitting limit @frontend/src/app/chatbot/page.tsx#252-337.
- **Plan**:
  - Build a dedicated “Usage Meter” component with radial progress, numeric stats, and live countdown.
  - Show contextual copy for authenticated vs guest users.
  - Provide “Why limited?” explainer and CTA to wait/upgrade (future monetization hook).
- **Acceptance**: Users can always see remaining/total, next reset time, and what to do when depleted.

### 3. Persona / Mode toggler (Goggins-inspired)
- **Problem**: No way to switch assistant voice; Goggins Mode lives in a separate FAB/dialog, fragmenting experience @frontend/src/components/goggins/GogginsFab.tsx#8-37.
- **Plan**:
  - Add inline mode picker with personas (e.g., “Executive”, “Project Deep Dive”, “Goggins Mode”).
  - For Goggins: reuse existing mutation & rate limiter but surface inside assistant UI; include explicit-mode toggle + disclaimers.
  - Persist last-used mode per user (localStorage + future profile setting).
- **Acceptance**: Users can switch personas mid-convo; rate limits per mode are communicated; legacy FAB optional.

### 4. Conversation UX overhaul
- **Problem**: Messages share same style, markdown area scrolls awkwardly, and suggestions disappear quickly @frontend/src/app/chatbot/page.tsx#263-407.
- **Plan**:
  - Introduce message grouping, avatars, status ticks, and better streaming/loading indicators.
  - Allow suggested prompts carousel + quick filters even after conversation starts.
  - Add inline system banners (auth required, rate limited, errors) inside transcript rather than separate alerts.
- **Acceptance**: Transcript feels polished, accessible, and resilient to long answers; suggestions remain discoverable.

### 5. Authentication & trust bar
- **Problem**: Auth alert feels detached and doesn’t explain benefits/requirements @frontend/src/app/chatbot/page.tsx#300-325.
- **Plan**:
  - Move auth messaging into info rail with tiered benefits (guest preview vs logged-in power usage).
  - Add microcopy on privacy, data retention, and “training corpus” to build trust.
  - Provide one-click login/register buttons + stateful copy when already logged in.
- **Acceptance**: Users immediately know whether they’re logged in, what access they have, and how to upgrade.

### 6. Observability & instrumentation
- **Problem**: No structured metrics for rate-limit hits, persona usage, or drop-offs.
- **Plan**:
  - Emit client-side events (e.g., `assistant.rate_limit.hit`, `assistant.mode.change`) to existing analytics layer or console placeholder.
  - Add logging hooks when countdown starts/resets to correlate with backend Redis data.
  - Document future backend metrics alignment (Redis keys, GraphQL extensions).
- **Acceptance**: We can track usage patterns without digging through console logs; documentation exists for future instrumentation.

## Next Steps
1. Align on visual direction (color palette, typography, motion) for new layout.
2. Break rebuild into feature branches per issue above.
3. Implement UI kit components (Usage Meter, Mode Picker, Info Rail cards).
4. Wire GraphQL + local state updates to feed new components.
