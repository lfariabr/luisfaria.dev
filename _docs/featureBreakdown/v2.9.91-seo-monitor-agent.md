## Overview

Implements an automated SEO monitoring pipeline with two checks: (A) live page audits fetched from the production sitemap, and (B) local markdown content audits for dev.to articles. Results are reported to Discord weekly via GitHub Actions.

## Problem

- No way to detect SEO regressions after the v2.8 overhaul (e.g., a broken metadata template, missing og:image)
- New articles added to `_docs/buildInPublic/devTo/` have no pre-publish quality gate (missing tags, low word count, broken links)
- Fully manual — SEO health was only visible by opening DevTools on each page

## Changes

### 1. `backend/scripts/seo-audit.ts`

**Check A — Live page audit:**
- Fetches `https://luisfaria.dev/sitemap.xml` and extracts all article/project URLs
- For each URL: fetches raw HTML and checks for `<title>` (non-generic), `<meta name="description">`, `og:title`, `og:image`, `application/ld+json`
- Requests are batched at max 5 concurrent to avoid hammering the server
- Exits non-zero if overall score < 80% (CI-enforceable)

**Check B — Markdown content audit:**
- Scans all `_docs/buildInPublic/devTo/**/*.md` files
- Per file checks: H1 title present, ≥ 3 tags on Tags/Hashtags line, ≥ 300 word count, no broken relative links

**Output modes:**
- Default: pretty-printed table to stdout (local runs)
- `--discord`: posts a rich embed to `DISCORD_WEBHOOK_URL` (GitHub Actions)

### 2. `.github/workflows/seo-monitor.yml`

- Schedule: `cron('0 9 * * 1')` — every Monday 9am UTC
- `workflow_dispatch` for manual on-demand runs
- Reuses existing `DISCORD_WEBHOOK_URL` secret — no new secrets
- Fallback `if: failure()` step if the script itself crashes before posting
