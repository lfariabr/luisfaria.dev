## Problem and Changes

### #374 — fix(places): hide Support FAB on /places

#### Problem

On `/places` the Support FAB (coffee button) sits bottom-right, over the map's zoom controls and the last timeline item on a phone. The page is private to two people, so a support prompt there has no purpose.

`StripeFab.tsx` already hides itself on `/notes` with an inline path check.

#### Work

- Hide the Support FAB on `/places` and anything under it. Move the hidden paths into one list instead of adding a second inline condition.
- Other FABs in the FAB stack are untouched.

#### Acceptance Criteria

- [ ] No Support FAB on `/places` (desktop and mobile)
- [ ] Still hidden on `/notes`; still shown on `/` and other public pages
- [ ] Test covers `/places`, `/places/...` and a public route

### #370 — fix(places): Date and Spent fields overlap in the mobile form

#### Problem

In the add/edit form on a phone, the Date and Spent (AUD) fields overlap. `PinFormDialog.tsx` puts them in `grid grid-cols-2`. iOS Safari gives `<input type="date">` a wide minimum width, and grid items default to `min-width: auto`, so the date input overflows its column into Spent. Category / Payment use the same grid and are at risk on narrow screens.

#### Work

- Let the grid children and inputs shrink: `min-w-0` on the items and a full-width date input.
- Stack Date and Spent into one column below `sm` if they still don't fit at 360px wide.
- Apply the same fix to the Category / Payment row.

#### Acceptance Criteria

- [ ] No overlap at 360px and 390px wide, in iPhone Safari and Android Chrome, for add and edit
- [ ] Error text under a field does not push into its neighbour
- [ ] Desktop layout unchanged

### #371 — feat(places): compact header — stat pills and a shorter map hint

#### Problem

On a phone the top of `/places` uses a lot of height before the map:
- three stacked cards (`grid sm:grid-cols-3`): places · visits, total spent, latest date
- the legend row, including "Precise home address intentionally not shown."
- the map card title "Click a marker or list item to see details"

#### Work

- Replace the three cards with three small pills on one line that wraps when needed, with the same icons: `📍 23 places · 40 visits`, `$ 1,234`, `📅 3 Oct 2026`.
- Shorten the map hint to "Tap a pin for details" on mobile, or drop it below `sm`. Keep it on desktop if it reads well.
- Tighten the legend: the home-address note can move into the home marker's popup.

#### Acceptance Criteria

- [ ] At 390px wide, the map starts in the first screen without scrolling
- [ ] Stats still show loading and empty states ("No visits yet")
- [ ] Map page tests updated for the new markup

### #372 — feat(places): Visit timeline shows the latest 3 with See more

#### Problem

Visit timeline renders every pin (40 today, growing) in a scrolling card up to 620px tall. On a phone it is a long list under the map.

#### Work

- Show the 3 most recent visits, then a "See more (37)" button that expands the list in place, and "Show less" to collapse it again.
- Expanding keeps the existing card scroll limit on desktop.
- Selecting a visit, and the per-visit Edit, still work in both states.

#### Acceptance Criteria

- [ ] 3 visits by default, newest first; button shows the hidden count

- [ ] Adding a visit shows it in the top 3 straight away
- [ ] Tests for 0, 3 and more than 3 visits

### #369 — fix(places): stop page pinch-zoom hijacking the map on mobile

#### Problem

On a phone the map uses `gestureHandling="cooperative"`: one finger scrolls the page, two fingers move the map. When a pinch starts with a finger off the map, the browser zooms the whole page instead. The page then sits zoomed in, the map fills the screen, and getting back out is fiddly. The experience is broken.

#### Options

| Option | Effect | Catch |
|---|---|---|
| `export const viewport = { maximumScale: 1 }` on `app/places/page.tsx` (Next 16 supports per-page `viewport`) | Android Chrome stops page pinch zoom | iOS Safari has ignored `maximum-scale` and `user-scalable=no` for pinch since iOS 10 |
| `touch-action: pan-x pan-y` on the page wrapper, not on the map | Browser pinch zoom is blocked over the page chrome; the map keeps its own gestures | Needs testing on a real iPhone; WebKit's support for pan values is recent |
| `gestureHandling="greedy"` | One finger pans the map | The page can't be scrolled past a map that is 68vh tall, so this is worse |

Recommended: the first two together, scoped to `/places` only. Disabling zoom is an accessibility cost, which is acceptable on a private two-person page and not acceptable site-wide. Text stays at least 16px so nothing needs zooming.

#### Acceptance Criteria

- [ ] On iPhone Safari and Android Chrome, a pinch that starts off the map does not zoom the page
- [ ] A two-finger pinch on the map still zooms the map; one finger still scrolls the page
- [ ] Other routes keep normal page zoom (viewport and touch-action scoped to `/places`)
- [ ] Verified on a real phone; the PR notes which devices and browsers

### #373 — docs(places): README and run-your-own guide for open-source readers

#### Problem

Places is meant to be shown off in a dev.to article and a LinkedIn post, but someone who wants to run their own copy would struggle:

- `README.md` still describes v3.6: "admin-only at `/admin/relationship`", with no mention of PARTNER, the add/edit form, Places API (New), the geocoding key or the importer.
- The setup traps we hit in production are written down nowhere for a reader:
  - Billing must be enabled for Places API (New).
  - The Geocoding key is separate from the browser key.
  - The nginx CSP `connect-src` needs `https://places.googleapis.com`, or search fails with an opaque `xhr error, error code 6`.
  - Advanced Markers need a Map ID.
- Sydney, AUD and `en-AU` are hard-coded in `RelationshipMap.tsx`, and the importer's `--allow-fallback` falls back to Sydney CBD.

#### Work

- **README: "Places" section** replacing the v3.6 text:
  - what it is
  - who can see it
  - env vars (frontend key, Map ID, backend geocoding key)
  - Google Cloud setup checklist
  - the CSP line
  - importer usage with the fictional CSV template (Corner Cafe, Harbour Bistro)
- **`_docs/guides/run-your-own-places-map.md`**: a step-by-step guide from spreadsheet to map: export the CSV, `--preview`, import, then add from your phone. The README and the article link here.
- **Optional: config instead of constants.** Default map centre, currency and locale come from `NEXT_PUBLIC_PLACES_*` env vars, defaulting to today's values. Do this only if it stays small.
- No real pins, amounts or home location in the docs or screenshots.

#### Acceptance Criteria

- [ ] README Places section matches v3.25 behaviour, with no `/admin/relationship` left
- [ ] A reader can go from a blank Google Cloud project to a working map using only the guide
- [ ] All examples use fictional data
