**Docs issue:** [#290](https://github.com/lfariabr/luisfaria.dev/issues/290)

**Summary:**
Eleven Dependabot PRs had piled up and 27 security alerts were open on `master` (2 critical, 19 high, 6 moderate). Five of those alerts had no Dependabot PR at all. The production droplet was also still on Ubuntu 25.10, which is no longer supported, and Docker had quietly stopped receiving updates.

This release merges every dependency update as one PR, fixes the alerts Dependabot couldn't reach, and brings the server up to Ubuntu 26.04 LTS with a current Docker Engine.

## Problem

1. **Dependabot backlog.** 11 open PRs, all green. Merging them one by one would have meant 11 lockfile rewrites and 11 commits of noise.
2. **Alerts with no PR.** 5 of the 27 alerts had no Dependabot PR, because something in the dependency tree blocked the fix:
   - `qs` (2 alerts): `express@4` and `body-parser@1` require `~6.15.1`, but the fix is in `6.16.0`.
   - `immutable` (2 alerts) and `tar` (1 alert): the `overrides` block in `frontend/package.json` pinned exact versions (`3.8.3`, `7.5.16`). Those pins had been added for an earlier security fix and were now stopping the next one.
3. **Unsupported OS.** The droplet ran Ubuntu 25.10, a short-term release whose support had ended. The login banner said so: `Your Ubuntu release is not supported anymore.`
4. **Docker frozen in place.** Docker Engine was still on the Ubuntu 24.10 (`oracular`) packages. Its apt source file had disappeared during an earlier release upgrade, so apt kept reporting `0 updates can be applied` while Docker fell further behind.

## Known Tooling Notes

- **Backend `npm ci` can fail locally** with `ENOENT: rename ... mongodb-macos-arm64-6.0.14.tgz.downloading`. Two copies of `mongodb-memory-server` (9.5.0, and 9.2.0 nested under `@shelf/jest-mongodb`) run their postinstall scripts at the same time, both download the same MongoDB binary into the same cache folder, and they collide on the final rename. This also happens on `master`. Workaround: `npm ci --foreground-scripts`.
- The compose file still starts with `version: '3.8'`. Compose 5 ignores it and prints an "obsolete" warning.

## Non-Goals

- Did not migrate to Express 5. The `qs` override covers the vulnerability until then.
- Did not upgrade MongoDB (`mongo:4.4`).
- Did not change application code, GraphQL schemas, or UI.
