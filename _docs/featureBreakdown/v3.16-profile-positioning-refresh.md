**Summary:**
The homepage had the right raw proof but still read too broadly: generic “What I do” labels, a stack list that looked like a standard senior-engineer portfolio, repeated Impact links pointing to the same article, stale proof counts, and primary navigation that sent visitors to internal archive pages before the stronger Dev.to writing surface.

## Problem

The previous homepage was directionally correct but had four issues:

1. **Positioning drift** — `POSITIONING.headline` changed, but the actual accessible/SEO H1 still used the older canonical phrase.
2. **Generic capability labels** — `Software Engineering`, `Data Engineering`, `Automation & DevOps`, and `AI / ML` were accurate but sounded like a template.
3. **Weak navigation priority** — `/projects` and `/articles` were primary nav items even though `/work` and Dev.to are stronger public proof surfaces.
4. **Repeated evidence links** — several Impact items pointed to the same parent-portal article, making the proof surface feel narrower than it is.

## Changes

### 1. Homepage positioning

Updated `frontend/src/content/profile.ts`:

- `badge`: `Education Data · Applied ML · Agentic Delivery`
- `headline`: `I build data systems that survive real users, audits, and handover.`
- `subline`: now names SQL Server, Power BI, Next.js, secure school data products, applied ML, and public agentic AI workflows.

The rotating hero frame changed from `Full-Stack Systems` to `Agentic AI`, and the production-proof clause now reads grammatically as `that survive go-live.`

### 2. Hero H1 source of truth

PR review caught a real issue: `POSITIONING.headline` was updated, but `HERO_CANONICAL_PHRASE` still locked the old accessible/SEO H1.

Fix:

```ts
export const HERO_CANONICAL_PHRASE = POSITIONING.headline;
```

This prevents future copy drift between the homepage positioning and the H1 used by screen readers and SEO.

### 3. Primary navigation

Changed the public header nav:

| Before | After |
|---|---|
| Home | Home |
| Work | Work |
| Projects | — |
| Articles | Writing → Dev.to |
| About | About |

Rationale:

- `/work` is stronger than a broad `/projects` archive.
- Dev.to is the stronger writing surface than the internal `/articles` index.
- Internal project/article routes remain available for SEO, footer navigation, and direct links.

### 4. `What I do`

Replaced generic pillars with current operating lanes:

- Secure education systems
- Data engineering & analytics
- Applied ML systems
- Agentic AI delivery

The blurbs now describe the work in terms of constraints and outcomes: authorization, privacy, auditability, SQL/Power BI reporting, evaluation contracts, artifact provenance, source truth, review gates, and redaction.

### 5. Core stack

Reclassified the stack into how the work is actually delivered:

- Production systems
- Data & analytics
- Applied ML
- Delivery & agents

This reduces the “generic portfolio stack” feel and makes the tools read as an operating model.

### 6. Impact evidence

Changed `Reliability & security` to `Reliability & delivery`.

The section now includes automated CI/CD deploy-pipeline evidence:

- `500+` automated tests behind a CI release gate → CI/CD pipeline article
- `CI/CD` automated deploy path with GHCR, Docker Compose, and rollback → CI/CD pipeline article

This keeps the parent-portal security proof but adds a separate delivery/reliability receipt.

### 7. Data synchronization

Updated related copies so public surfaces do not contradict each other:

- About page: Master’s repo count now `1,400+`.
- ReviewPulse case study: public commit count now `200+`.
- Backend profile data: ReviewPulse and Agentic Study Pipeline impact values updated.
- Homepage test assertions updated for the new nav and copy.
