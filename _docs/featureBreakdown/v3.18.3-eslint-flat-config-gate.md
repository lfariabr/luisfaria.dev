# v3.18.3 — Frontend ESLint: Native Flat Config + CI Gate

## GitHub Issue

**Issue:** [#299](https://github.com/lfariabr/luisfaria.dev/issues/299)

**Title:** `Frontend ESLint crashes on load and is silently ignored in CI`

**Summary:**
Frontend lint had been broken and invisible. The config crashed on load, `next lint` no longer exists in Next 16, and CI swallowed the failure with `|| true`. With a working config, lint reported 44 errors.

## Acceptance Criteria

- [x] `npm run lint` runs without crashing
- [x] 0 lint errors

---

## Overview

Restore frontend linting, fix every error it surfaces, and make it a real merge gate. Warnings (66) are deferred to a follow-up.

## Problem

1. `eslint.config.mjs` wrapped `next/core-web-vitals` / `next/typescript` in `FlatCompat`. `eslint-config-next` 16 already exports native flat configs, so the compat layer crashed: `TypeError: Converting circular structure to JSON`.
2. `"lint": "next lint"` — removed in Next 16.
3. `.github/workflows/ci.yml` ran `npm run lint || true`, so nothing ever failed.

## Changes

### 1. Config, script, CI
- `eslint.config.mjs` spreads `eslint-config-next/core-web-vitals` and `/typescript` directly, ignores build output, and allows CommonJS `require` in root `*.js` (Jest config files).
- `"lint": "eslint ."`
- CI: `npm run lint` without `|| true`.

### 2. Mechanical fixes (19)
- **Unescaped entities (11):** `&apos;` / `&quot;` — renders identically. The `test-sentry` console snippet uses string literals so the copied code keeps straight quotes.
- **Empty interfaces (3):** `TextareaProps`, `ArticleUpdateInput`, `ProjectUpdateInput` → type aliases.
- **Jest config (5):** `require` allowed for root `*.js`; dropped two no-op `@ts-ignore` in `jest.setup.js`.

### 3. Typing (14)
- **`any` → real types (13):** `unknown` for gtag args and the RHF context generic; `ErrorLike` narrowing in `AuthContext.formatError`; react-markdown's `ExtraProps` for the markdown `Paragraph`; a shared `applyRateLimitExtensions` in `GogginsDialog` replacing two duplicated `any` blocks.
- **`display-name` (1):** named `Wrapper` in the Stripe hook test.

### 4. React hooks refactors (11)

| Component | Before | After |
|---|---|---|
| `NoteForm` | Effect re-copied `note` into state on every new object | Removed; edit form remounts with `key={note.id}`. **Also fixes a latent bug:** an Apollo refetch while editing wiped unsaved input. |
| `useRotatingText` | `setIsRotating(true)` in effect | `isRotating` derived from `useSyncExternalStore` on `prefers-reduced-motion` (server snapshot `false`, so no hydration mismatch). Now also reacts live to preference changes. |
| `ProjectForm` | `isMounted` set in effect | New `useIsClient()` hook (`useSyncExternalStore`) |
| Login page | Effect mirrored auth `error` into local state | Prop-change adjustment during render; seeded with any existing error to keep mount behaviour |
| `ApodDialog` (4) | Reset-on-logout, reset-on-close ×2, "Read more" measurement | Prop-change adjustments; "Read more" derives the char-count check in render and the effect only reads layout from the ref |
| Chatbot (2) | Callbacks used before declaration (`immutability`) | Declared above the effect that uses them |

**Justified disables (3):** effects that sync a wall-clock countdown or fire transition notices from external rate-limit data. `Date.now()` can't run during render (`react-hooks/purity`), and rewriting the chatbot notices into mutation handlers is a behaviour change better done with tests:
- `ApodDialog` rate-limit sync
- chatbot countdown reset
- chatbot rate-status transition notices
