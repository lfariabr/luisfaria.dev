# v3.29 — Places: full screen map with one-finger pan

## GitHub Issue

**#398 feat(places): fullscreen map with one-finger pan**

Deferred from epic #388. On the page the map uses `gestureHandling="cooperative"`, so a phone needs two fingers to move it. A full screen mode can switch to `greedy`, where one finger pans.

### Acceptance Criteria

- [x] A 44px button on the map enters and leaves full screen
- [x] Full screen uses `greedy`; the page uses `cooperative`
- [x] Works on iPhone Safari, which has no element Fullscreen API
- [x] The page behind can't scroll; Escape leaves (unless the pin form is open)
- [ ] iPhone: no page pinch zoom in either mode (checks #369 / #387 / #402 still hold)

## Overview

The map card turns into a fixed layer over the whole viewport, so no browser API is needed. Google's own full screen control is turned off because it relies on the Fullscreen API.

## Problem

Exploring the map on a phone took two fingers, which is awkward with one hand. Google's built-in full screen button doesn't appear on iPhone Safari at all.

## Changes

| File | Change |
|------|--------|
| `frontend/src/components/relationship/RelationshipMap.tsx` | `fullscreen` state. The card goes `fixed inset-0 z-40` with safe-area padding, and the map fills it. `gestureHandling` switches between `greedy` and `cooperative`, and `fullscreenControl={false}`. An overlay button toggles the mode (`aria-pressed`). An effect locks body scroll and listens for Escape. |
| `frontend/src/__tests__/app/RelationshipMapPage.test.tsx` | The Map mock exposes `gestureHandling`. Three new tests. |

`z-40` keeps the pin form dialog (`z-50`) above the full screen map.

## Verification

- `npx jest`: 350 passed. `npm run lint` and `tsc --noEmit` are clean.
- iPhone, after deploy: one finger pans in full screen, the page doesn't zoom, and the cooperative mode on the page is unchanged.
