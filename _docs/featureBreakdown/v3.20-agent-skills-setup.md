**Summary:**
Claude Code sessions on this repo got Matt Pocock's engineering skills only because the plugin was installed at user scope on one machine. This commits the plugin at project scope and scaffolds that config so the skills behave the same on any clone.

## Overview

Matt Pocock's `mattpocock-skills` plugin (official Claude Code marketplace, v1.2.3) bundles the engineering loop this repo already follows by hand: grill the plan, write a spec to the issue tracker, implement with TDD, review on two axes before committing. This change makes the plugin part of the repo rather than one developer's machine, and runs the plugin's one-time setup so the skills know where issues live and how the domain docs are laid out.

## Problem

1. **Plugin lived at user scope only.** `~/.claude/settings.json` enabled it; a fresh clone had no idea the skills existed.
2. **No per-repo config.** `to-spec`, `to-tickets`, `triage` and `wayfinder` need to know the tracker is GitHub Issues via `gh`. `domain-modeling`, `grill-with-docs`, `code-review` and `tdd` need to know where `CONTEXT.md` and ADRs go.
3. **Triage vocabulary missing on GitHub.** Only `wontfix` existed, so `/triage` would have created labels ad hoc on first use.

## Changes

### 1. Project-scope plugin (`.claude/settings.json`)
New committed file with `enabledPlugins` set for `mattpocock-skills@claude-plugins-official`. Claude Code merges this with the user-scope entry, so nothing duplicates for the maintainer and new clones are prompted to install it. The skills.sh copy-into-repo route was deliberately not used: the plugin README warns that having both yields every skill twice.

### 2. `CLAUDE.md` — `## Agent skills` section
Three sub-sections (issue tracker, triage labels, domain docs), each one line plus a pointer to the matching file under `docs/agents/`. Nothing else in the file changed.

### 3. `docs/agents/` (generated by `/setup-matt-pocock-skills`)
| File | Content |
|---|---|
| `issue-tracker.md` | GitHub Issues via `gh`; "PRs as a request surface" left **off**; wayfinder map/child/blocking conventions |
| `triage-labels.md` | The five canonical roles mapped 1:1 to repo labels |
| `domain.md` | Single-context layout: root `CONTEXT.md` + `docs/adr/`, created lazily; glossary-vocabulary and ADR-conflict rules |

### 4. GitHub labels
Created `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`. `wontfix` already existed.
