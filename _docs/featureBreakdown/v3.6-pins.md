## Goal

Build and harden a private admin-only map of relationship outings in Sydney. The feature turns finance-export entries into geocoded pins, shows spend/date context, and keeps the implementation safe enough to extend later into analytics or sharing.

Non-goal for v3.6: public sharing. The map remains private behind existing admin auth.

---

## Current Implementation

### Backend

- `Pin` Mongoose model stores `date`, `placeName`, `amount`, `lat`, `lng`, `category`, `payment`, `city`, `countryCode`, `notes`, and `source`.
- Model validation enforces coordinate bounds and string length limits.
- Indexes:
  - `{ date: -1 }`
  - `{ city: 1, date: -1 }`
  - unique duplicate guard on `{ placeName: 1, date: 1, amount: 1 }`
- GraphQL exposes admin-only `pins`, `createPin`, and `relationshipHomeLocation`.
- `PinInput` is validated with Zod through GraphQL Shield before resolver execution.
- Pin resolvers use typed context and the shared `createErrorHandler` pattern.
- `date` and `createdAt` serialize as ISO strings via resolver field mappings.
- `relationshipHomeLocation` returns `{ label, lat, lng }` parsed from optional `RELATIONSHIP_HOME_*` backend env vars (see Privacy section). Returns `null` when env is missing or invalid; the backend boots either way.

### Seed / Import

Initial seeding is performed locally via an uncommitted helper. The script itself is not part of this PR — it is gitignored to keep private finance-export data out of version control. Future iterations may ship a sanitized generic importer.

### Frontend

- `/admin/relationship` renders the private admin map using `@vis.gl/react-google-maps`.
- Summary cards show place count, total spend, and latest visit date.
- Map states cover loading, GraphQL error with retry, empty data, and missing Google Maps browser key.
- A side timeline lists visits by date so inspection does not depend only on marker hunting.
- Clicking a marker or timeline item opens an InfoWindow with place, date, amount, category, and payment.
- Gesture handling is cooperative to avoid hijacking scroll.
- An optional amber "Home base" marker renders only when the admin-only `relationshipHomeLocation` query returns data. It shows the configured label only — never coordinates, never a street address.

## Security And Privacy Decisions

- Admin protection exists at multiple layers: Next middleware/admin layout and GraphQL Shield.
- No precise street address is shown anywhere — UI, logs, GraphQL responses, or client bundle.
- No home coordinates are committed or bundled into frontend source. The exact lat/lng never appears in tracked files; they live only in `backend/.env` (gitignored) and flow through an admin-authenticated GraphQL response.
- Admins may see an optional env-backed "Home base" marker via the admin-only `relationshipHomeLocation` GraphQL query. The query is guarded by GraphQL Shield's `isAdmin` rule. When the env is unset, the query returns `null` and no marker is shown.
- The home InfoWindow renders only the label string (default "Home base"). No coordinates or address are rendered.
- Browser Maps key remains public by design because Maps JavaScript API runs client-side. It must be restricted by HTTP referrer and API scope in Google Cloud.
- Server geocoding key is separate, documented as backend-only, and is not required for backend boot.
- Pin mutation input rejects invalid dates, empty place names, impossible coordinates, malformed country codes, and oversized optional strings.

Environment guidance:

```bash
# frontend/.env.local — browser-side
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=
NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID=

# backend/.env — backend-only, gitignored
GEOCODING_API_KEY=                  # optional; only used by local seed helper
RELATIONSHIP_HOME_LAT=              # optional; admin-only home marker
RELATIONSHIP_HOME_LNG=              # optional; admin-only home marker
RELATIONSHIP_HOME_LABEL="Home base" # optional; defaults to "Home base"
```

Google Cloud restrictions and notes:

- `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`: restrict to Maps JavaScript API and trusted HTTP referrers such as `https://luisfaria.dev/*`.
- `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID`: required for `AdvancedMarker` rendering. Create one in Google Cloud Console → Maps → Map Management with **Advanced Markers** enabled. `DEMO_MAP_ID` is for local/testing only and is rate-limited. If unset, the page renders a graceful fallback similar to the missing-API-key state.
- `GEOCODING_API_KEY`: restrict to Geocoding API only. Do not expose it through `NEXT_PUBLIC_*`.
- `RELATIONSHIP_HOME_*`: backend-only. Never expose via `NEXT_PUBLIC_*` — that would inline the values into the browser bundle.
