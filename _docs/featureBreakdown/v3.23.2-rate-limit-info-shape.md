## Overview

Every Visible rate limit now answers in the same shape, `{ limit, remaining, resetTime }`, on success and in the `RATE_LIMITED` error, and every client computes its countdown from `resetTime`.

## Problem

1. **Two time fields.** Goggins read `resetIn` (seconds), chatbot and APOD read `resetTime` (ISO). #339 kept both, with `allowed` / `resetIn` marked deprecated.
2. **A dead path in Goggins.** The dialog handled `allowed === false` on a successful response, which the server never sends: over the limit is always the `RATE_LIMITED` error.
3. **A Goggins-only wrapper** in `screams/mutations.ts` existed only to add `resetIn` to the error.
4. **Dead code:** `schemas/types/shared/RateLimitInfo.ts`, a `GraphQLObjectType` nothing imported.

## Changes

### 1. Backend
- `RateLimitInfo` is `{ limit: Int!, remaining: Int!, resetTime: String! }`.
- `Errors.rateLimited({ limit, remaining, resetTime })`: no `resetIn`.
- `activateGogginsMode` calls `enforceRateLimit('goggins', Subject.email(...))` like every other resolver.
- `schemas/types/shared/RateLimitInfo.ts` deleted.

### 2. Frontend (`GogginsDialog.tsx`, `scream.mutations.ts`)
- Mutation selects `limit`, `remaining`, `resetTime`.
- Countdown is `ceil((resetTime − now) / 1000)`, started on a `RATE_LIMITED` error, or on success when `remaining` hits 0.
- `allowed === false` branch and its "Rate limited." text removed. A `SERVICE_UNAVAILABLE` error shows its message with no countdown.

### 3. Tests
- `GogginsDialog.rate-limit.test.tsx` rewritten for `resetTime` (4 tests). The byte-identical copy under `__tests__/app/` was deleted.
- `screamResolvers.test.ts` asserts the new shape and that the error carries no `resetIn`.
